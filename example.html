Overview

Three parts, one round trip

On the left is the app a person uses. In the middle is the server. On the right is the data it keeps. Every request goes app to server to data, and the answer comes back the same way.

Today's ask comes from :

Who's asking

The server checks who's asking first

Each request carries a token that says who sent it. The server reads it before doing anything, and runs the request as that person.

Signed in.
No token. The server refuses, and nothing is read.
The data

It reads only what that person may see

The server looks up and returns only the fields this person is allowed to see.

    Two things people get wrong

    Myth

    "The app decides what I can see"

    The server decides, from the token. The app only shows what comes back.

    Myth

    "No token means read-only"

    No token means nothing at all.
